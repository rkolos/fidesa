## 5. Специфікація кожної секції

Формат: ієрархія → desktop/mobile → антипатерни §0A (чого уникати).

### 5.0. Header

**Ієрархія:** skip link → logo+wordmark «Fidesa» → nav → domain `EN` → primary CTA. Mobile: logo | короткий CTA `Дзвінок` | hamburger; пункти nav + `EN` у drawer.

**Mobile:** sticky; touch targets ≥44px; drawer не дає horizontal overflow; мовне посилання тільки в drawer на вузьких екранах.

**Антипатерни §0A:** не дрібнити бренд-знак так, щоб H1 «кричав» сильніше за Fidesa (анти-Everstar); не жовті/amber CTA; не dual CTA «Post a Job / Join Community».

---

### 5.1. Hero

**Ієрархія (перший viewport — один склад):**  
1) Brand `Fidesa` (hero-level)  
2) H1  
3) один supporting абзац  
4) CTA-група (primary + secondary)  
5) full-bleed фон (navy або engineering-фото з navy overlay 60–70%)

**Desktop:** max content width ~1120–1200px; бренд не слабший за H1; без карток, badges, stats.

**Mobile:** `min-height: 100svh`, але CTA завжди в першому екрані на типових 375×667; якщо тісно — скорочувати supporting, **не** ховати CTA. Не iframe Calendly у hero.

**Антипатерни §0A:**

- Не cream/beige paper-фон (Everstar).
- Не dark+amber/yellow CTA (BazaIT / ITExpert).
- Не stats strip («N years / 100% Victory»).
- Не стокові рукостискання як головний візуал.
- Не lead-форма в hero.
- Не candidate-first чіпи «ми шукаємо».
- Не overlays: floating badges, promo chips на медіа.

---

### 5.2. About

**Ієрархія:** H2 → lead (одне декларативне речення) → body → Q→A (3).

**Desktop:** одна колонка, readable measure; чергування `--surface` / `--bg` відносно сусідів.

**Mobile:** вертикальний стек; Q/A без акордеону-залежності від JS (відкритий текст або native `<details>`).

**Антипатерни:** не сітка 6–12 сервісних карток; не місія «перемога» як вісь; не dual audience centering на кандидатів.

---

### 5.3. Process

**Ієрархія:** H2 → intro → 4 кроки (номер + title + body) → мікрокопія + лінійна іконка рук.

**Desktop від `md`:** 2×2 або горизонтальний ряд з роздільниками 1px; без тіньових карток як маркетингового дефолту.

**Mobile:** вертикальний нумерований стек; іконка не штовхає текст за viewport.

**Антипатерни:** не product/platform мова; не pricing tiers під кроками.

---

### 5.4. Why Fidesa

**Ієрархія:** H2 → intro → Підблок A (H3 + список + Q/A) → Підблок B (H3 + список + Q/A).

**Desktop від `md`:** дві колонки (A | B).  
**Mobile:** стек A потім B.

**Антипатерни:** не виносити безпеку як єдиний hero-меседж сайту (безпека — причина обрати, спеціалізація — головне); не публікувати % комісій / PDF presentation; не «absolute security» гарантії без disclaimer Q/A.

---

### 5.5. Team

**Ієрархія:** H2 → intro → профіль Валерії (фото → ім’я → role → bio) → блок CTO (title → trust line).

**Desktop від `md`:** фото | текст side-by-side допустимо.  
**Mobile:** фото full-bleed у колонці, біо під ним (стек); не side-by-side до `md`.

**Антипатерни:** не стіна команди з 10+ плиток; не клієнтські логотипи; не вигадувати ПІБ CTO.

---

### 5.6. Testimonials stub

**Ієрархія:** H2 → empty state paragraph → порожній `data-testimonials`.

**Mobile/Desktop:** без карток, без каруселі, без «сірих» фейкових відгуків.

**Антипатерни:** не client logo wall (ITExpert); не QR/community trust substitutes (BazaIT).

---

### 5.7. Contact

**Ієрархія:** H2 → supporting → CTA / Calendly placeholder → email → location.

**Desktop:** контент + зона календаря; iframe лише після interaction або IO (не в hero-бандлі).

**Mobile:** кнопка на повну ширину; не розгортати важкий iframe на весь екран без дії користувача; fallback-лінк завжди в HTML.

**Антипатерни:** не mailto як primary B2B CTA; не Chatwoot/live-chat; не форма «Залишити резюме» на home.

---

### 5.8. Footer

**Ієрархія:** brand + tagline → лінки → декор SVG → ©.

**Mobile:** стек лінків; довгі URL wrap; без horizontal overflow.

**Антипатерни:** не золотий лавр/статуї; не згадки материнських структур.

## 6. Schema Organization — notes (без коду)

На головній UK додати JSON-LD (окремий `<script type="application/ld+json">`). Типи: **`Organization`** і за потреби **`ProfessionalService`** (можна як `@type` масив або окремий вузол, що посилається на Organization), плюс **`WebSite`**.

### 6.1. Organization / ProfessionalService — поля

| Поле | Значення / правило |
|---|---|
| `@context` | `https://schema.org` |
| `@type` | `Organization` і/або `ProfessionalService` |
| `name` | `Fidesa` |
| `url` | `https://fidesa.com.ua/` |
| `logo` | абсолютний URL до файлу логотипу (напр. `https://fidesa.com.ua/assets/brand/logo.svg`) |
| `description` | Коротко: спеціалізована рекрутингова агенція для Defence Tech (можна стиснути meta description) |
| `email` | `[EMAIL_PLACEHOLDER]` (підставити перед продом) |
| `areaServed` | Україна + міжнародні клієнти (текст або Country-список — без вигаданих юрофісів) |
| `knowsAbout` / ключовий фокус | Defence Tech recruiting, hiring for defence manufacturers, UAV, defence software (без клієнтських назв) |
| `sameAs` | лише реальні публічні профілі, якщо є; інакше **опустити** поле |
| **Заборонено** | будь-які згадки DNA325, parentOrganization на сторонні бренди, `priceRange` з публічними %, фейкові AggregateRating |

### 6.2. WebSite — поля

| Поле | Значення / правило |
|---|---|
| `@type` | `WebSite` |
| `name` | `Fidesa` |
| `url` | `https://fidesa.com.ua/` |
| `inLanguage` | `uk` |
| `publisher` | посилання/`@id` на Organization |
| `potentialAction` | **не** обов’язково SearchAction на v1 (немає site search) |

### 6.3. Що не додавати на home у Task 2

- `JobPosting` (лише на detail вакансій — Task 4)
- `BlogPosting` (Task 5)
- `BreadcrumbList` на home не обов’язковий
- Фейкові `Review` / testimonials у schema, поки модуль порожній
