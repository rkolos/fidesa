## 5. Доменна логіка (обов’язкова частина Task 3)

### 5.1. Два домени — ролі

| Домен | Роль | Мова на старті |
|---|---|---|
| `https://fidesa.com.ua` | Українська версія сайту | лише `uk`; без внутрішнього language select |
| `https://fidesa.agency` | Міжнародний багатомовний домен | `/en/` зараз; пізніше `/de/`, `/pl/` тощо |

Перемикач працює на **двох рівнях** (з ТЗ / мастер-плану):

1. **Між доменами:** com.ua ↔ agency (UA ↔ EN на старті).
2. **Всередині agency:** архітектура підмовних префіксів (`/en/…`); на v1 UI показує лише EN + лінк UA.

### 5.2. Redirect кореня agency

| З | На | Тип | Примітка |
|---|---|---|---|
| `https://fidesa.agency/` | `https://fidesa.agency/en/` | **302** (тимчасовий) або **308/301** після стабілізації — у мастер-плані: 302/canonical на `/en/` до появи інших мов | До появи 2+ мов на agency корінь не є контентною сторінкою |
| Canonical на `/en/` | `https://fidesa.agency/en/` | — | Користувач і боти мають канон на `/en/` |

Реалізація: CDN / hosting redirect rule (Netlify `_redirects`, Cloudflare Redirect Rules, nginx тощо) — **не** покладатися лише на JS `location.replace`. Без JS відкриття `/` має все одно потрапити на `/en/` через серверний редірект.

### 5.3. hreflang і canonical (правила)

На **кожній** парі відповідних сторінок:

| Тег | Значення |
|---|---|
| `rel="alternate" hreflang="uk"` | `https://fidesa.com.ua` + UK path |
| `rel="alternate" hreflang="en"` | `https://fidesa.agency/en` + EN path |
| `rel="alternate" hreflang="x-default"` | `https://fidesa.agency/en/` (міжнародний дефолт; для внутрішніх EN-сторінок — відповідний EN URL або home EN — зафіксувати: **x-default = EN home** на всіх сторінках v1, як у мастер-плані §5.1) |
| `rel="canonical"` | абсолютний URL **поточної** мовної сторінки |

**Home pair:**

- UK: canonical `https://fidesa.com.ua/` + hreflang як у Task 2 §2  
- EN: canonical `https://fidesa.agency/en/` + hreflang як у §2 цього документа  

Не ставити hreflang на неіснуючі майбутні `/de/` до їх появи.

### 5.4. Збереження path при зміні мови / домену

Мовне перемикання **не губить шлях** (мастер-план §7).

#### Path map (v1)

| UK (`fidesa.com.ua`) | EN (`fidesa.agency`) |
|---|---|
| `/` | `/en/` |
| `/vacancies/` | `/en/vacancies/` |
| `/vacancies/{slug}/` | `/en/vacancies/{slug}/` |
| `/blog/` | `/en/blog/` |
| `/blog/{slug}/` | `/en/blog/{slug}/` |
| `/blog/tag/{tag}/` | `/en/blog/tag/{tag}/` |
| `/privacy/` | `/en/privacy/` |
| `/#about` (і інші якорі) | `/en/#about` (ті самі fragment id) |

**Правила побудови URL для лінка UA|EN:**

1. Визначити «логічний path» без мовного префікса: на agency зрізати префікс `/en` (і майбутній `/de` тощо); на com.ua path уже без префікса.
2. Побудувати цільовий URL:  
   - на EN: `https://fidesa.agency/en` + logical path (+ query + hash);  
   - на UK: `https://fidesa.com.ua` + logical path (+ query + hash).
3. Зберігати `?query` (напр. фільтри вакансій) і `#hash`, якщо вони релевантні обом версіям.
4. Якщо для slug немає дзеркала в іншій мові — вест на list-сторінку тієї ж секції (`/vacancies/` ↔ `/en/vacancies/`), не на 404 чужого домену. (Повна матриця slug parity — відповідальність Tasks 4–5; на home достатньо map для `/` і `#section`.)

**Статичні href у HTML (без JS):** на home EN лінк `UA` може бути простим `https://fidesa.com.ua/`; на home UK — `https://fidesa.agency/en/`. Path-aware оновлення href — progressive enhancement у `domain-lang.js`.

### 5.5. Geo / Accept-Language банер

#### Де показується

| Сторінка | Банер |
|---|---|

Task 3 **обов’язково** реалізує банер на agency. Банер на com.ua — out of scope unless вже закладено в partial (не додавати без потреби). |

#### Коли показувати (agency)

Показати м’який банер **лише якщо всі** умови істинні:

1. Немає збереженого рішення в `localStorage` (§5.6) зі значенням «dismiss» / «stay-en» / «prefer-ua» (див. ключі нижче).
2. Сигнал «ймовірно UA»:  
   - `navigator.language` / `navigator.languages` містить `uk` або `uk-UA`, **або**  
   - (опційно, якщо інфра дає) geo ≈ Ukraine — **не** блокувати рендер сторінки очікуванням geo-API; Accept-Language — primary.
3. Користувач зараз на `fidesa.agency` (мовний префікс `/en/` на v1).

**Не робити:** автоматичний hard-redirect на com.ua без згоди; не замінювати HTML-контент EN на UK через JS.

| Dismiss (icon/`aria-label`) | `Закрити` |
| Checkbox / secondary persist (якщо один контроль) | `Більше не показувати` |

**Варіант B — той самий банер англійською** (якщо UI банера тримається в `lang=en` сторінки; допустимий альтернативний набір):

| Елемент | Текст |
|---|---|
| Message | `Looking for the Ukrainian version of this site?` |
| Primary CTA | `Go to fidesa.com.ua` |
| Secondary | `Stay in English` |
| Dismiss `aria-label` | `Dismiss` |
| Persist control | `Don’t show again` |

**Рекомендація реалізації:** на agency показувати **Варіант A (UK copy)** у банері при UA-сигналі — повідомлення рідною мовою; сторінка під банером лишається EN. Якщо один набір простіший для partial — зафіксувати A; B тримати як повний EN-дзеркало для a11y/`lang` узгодженості.

Primary CTA веде на path-aware `https://fidesa.com.ua{mapped-path}`.  
Secondary / dismiss лишає користувача на поточному EN URL і пише `localStorage`.

### 5.6. localStorage — правила

| Ключ (рекомендований) | Значення | Сенс |
|---|---|---|
| `fidesa.langChoice` | `en` \| `uk` \| `dismiss` | Останній явний вибір користувача |
| `fidesa.langBanner` | `hidden` | Банер більше не показувати («Більше не показувати» / dismiss з persist) |

**Альтернатива одним ключем** (якщо простіше): `fidesa.domainPref` = `agency-en` | `com-ua` | `no-banner`.

**Правила:**

1. Перший візит без ключа → можна показати банер за §5.5.
2. Клік «Перейти на fidesa.com.ua» → записати prefer-uk / `uk`; перейти path-aware на com.ua.
3. Клік «Залишитись англійською» або «Більше не показувати» → записати stay-en / `dismiss` + `langBanner=hidden`; банер сховати.
4. Клік лише «Закрити» без persist → сховати на цю сесію (`sessionStorage` опційно); при новому візиті можна показати знову, **якщо** немає `no-banner`.
5. Наявність `langBanner=hidden` або явного `en`/`uk` вибору → **не** показувати банер знову, навіть якщо Accept-Language = uk.
6. Ручний лінк `UA` / `EN` у header **завжди** працює незалежно від localStorage (не блокувати навігацію).
7. Не зберігати PII; лише preference flags. Ключі з префіксом `fidesa.` щоб не колізити.

### 5.7. Поведінка без JavaScript (критично для DoD)

| Сценарій | Очікування |
|---|---|
| Відкрито `https://fidesa.agency/en/` | Повний EN one-pager в HTML; усі секції §4 читабельні |
| Відкрито `https://fidesa.agency/` | Серверний redirect → `/en/` (працює без JS) |
| Відкрито `https://fidesa.com.ua/` | Повний UK one-pager (Task 2); лінк `EN` у HTML веде на `https://fidesa.agency/en/` |
| Geo-банер | **Відсутній** або hidden у HTML без JS — сторінка не зламана, контент EN видимий |
| Path-aware switch | Статичні href на home достатні; складний map — enhancement |
| Calendly | Видимий fallback-лінк `Open calendar on Calendly` |
| hreflang / canonical | У статичному `<head>`, не інжектяться лише скриптом |

**Принцип:** URL визначає мову. JS не «вгадує» мову контенту і не підміняє розмітку.

### 5.8. Header domain switch — підсумок UX
